# Ads Bridge 0.8.2 — installation and release limits

Compatible successor to stable 0.8.1, incorporating accepted dev.3 runtime and
updated administrator help. Inquiry schema 2, configuration tree 2, coordination
contract 1 and guard schema 1 remain unchanged. PHP minimum 8.3.

Install the exact release ZIP after backing up the plugin and preserving existing
configuration/data/journals. Serialize writes through the existing site executor;
brief site-only admission/drain and cache handling belong to the same installation
job. Verify all payload hashes and PHP lint with the actual site runtime. Do not
reactivate other plugins, reset history or change external configuration authority.

Normal activation/administrator setup prepares absent core storage through existing
protected additive routines. Existing compatible installations require no new core
schema migration. Incompatible/partial schemas and retained unfinished operations
remain protected: inspect and resume the original supported operation. The optional
development outcome tables are not required for form setup and are not provisioned
by this upgrade. Never apply their migration merely to make diagnostics green.

Use Setup's ordered workflow; save incomplete settings freely. Base owns shared
Business Data. Intentional external configuration can be retained or explicitly
switched to WordPress settings without importing unavailable files. Custom mappings,
Consent barriers, inquiry history and all export flags are preserved. See README
and the in-plugin Help / Reference page for each connection and verification step.

File rollback restores only this job's backed-up plugin files after checking for
later changes. Preserve any additive schema/data and journals. Never drop tables,
purge Consent audit/withdrawal barriers, rewind the whole cron option or restore the
whole database. A settings/ownership failure requires named recovery, not lock or
journal deletion. Do not downgrade while a new operation is active or pending.

Supported core: form inquiry/lifecycle/Consent gates, saved CRM configuration import,
four-area setup/compliance UI and append-only Sheets contracts. Real delivery stays
disabled on Alma. Service-account access and live customer delivery are not verified
by this release. The accepted synthetic worksheet demonstration is separate evidence.

FE production transport and lead/job continuity remain unavailable; no provider POST
is enabled. Call advertising remains held for the legitimate call Consent/provider
identity contract. No live call or Google call submission is claimed. Development
interfaces do not authorize production outcomes; synthetic policy is not a revenue
policy for actual business records. Stable publication is not client rollout.

The historical pre-0.8.0 raw serialized cron payload was not captured; its limitation
is retained, not a pending restoration task. Current hooks/arguments/configuration
are assessed without running jobs. Prior completed suites are carried forward;
new focused package/main-install results are published separately, not relabeled
as a fresh browser/provider acceptance campaign.
