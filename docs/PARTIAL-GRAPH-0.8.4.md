# Partially deleted configuration graphs — 0.8.4

A new import preserves the retired numeric identities in its reviewed bindings.
Missing definitions receive fresh IDs; surviving dependent bodies retain the
reviewed Keep/Replace choice and only necessary relationships are relinked.
Completed prior jobs and their receipts are not translated to replacement IDs.

The0.8.3 correction already retained old-reference preconditions and explicit
relink actions. A focused counterexample found that a newly appearing child under
its deleted parent's old numeric ID could escape a lookup scoped only to the new
ID.0.8.4 checks both scopes for funnel emails, steps and sequence emails when the
parent binding changed. Pending readback, post-save and final receipt verification
also refuse ambiguity. Foreign rows are never deleted or silently adopted.

Surviving edited HTML/settings/conditions remain intact. After-review deletion,
edit, collision, invalid identity and uncertain-create protections remain active.
A partial/hybrid or unknown write is held; this is not an automatic cleanup worker.

Upgrade only after the existing import is complete or through its exact supported
recovery. Preserve the prior package, registry, journals and configuration. Do not
reset a completed operation or replace the source of an active one. Deliberate
re-import gets a distinct reviewed operation and must reuse identical native IDs
without vendor saves when the definitions are already present.

No schema change, enrollment, mail, Google delivery or unrelated plugin change.
The existing form/Consent/inquiry/export contracts remain unchanged. Installed
verification and local partial/fault fixtures are reported separately; no local
double is described as native destructive-fault acceptance.
